# 수강신청과 일정 투표 백엔드 연동 사항

실제 서비스에 반영할 때 먼저 맞춰야 할 것은 **수강신청 시작·마감의 서버 검증**과 **신청일 전후에도 조회할 수 있는 개설 확정 수업 데이터**다. 아래 경로와 필드는 현재 프런트엔드가 사용하는 계약이다. 운영 API에서 이미 지원하는 항목은 연동 확인으로 마무리한다.

## 교사 제안 접수와 개설 확정

새 제안은 등록 즉시 `SURVEYING`으로 공개되고 대상 학년 학생의 관심 표시를 받는다. `TEACHER` 계정이 후보 시간 ID와 마감 시각을 정해 수락하면 수요조사가 끝나고 즉시 `VOTING`이 된다. 대상 학년 학생 전체가 투표할 수 있다. 마감 후 제안을 맡은 선생님이 후보 중 하나를 확정하면 수업의 담당자·정원·운영 시간이 개설 확정 목록에 반영된다. [교사 흐름 API 계약](API-CONTRACT.md#학교-선생님의-제안-수락과-개설-확정)

## 학교 공통 수강신청 일정

- 학교가 정한 신청일을 서버에서 설정한다. 현재 화면 기준으로 신청일은 한국 시간(`Asia/Seoul`) 00:00부터 다음 날 00:00 직전까지다. 날짜가 비어 있으면 신청을 닫는다.
- `POST /enrollments`와 `DELETE /enrollments/{enrollmentId}`는 직접 호출해도 서버 시각으로 신청 기간을 검증한다. 기간 밖에는 상태를 변경하지 않고 사용자가 이해할 수 있는 오류를 반환한다. 취소는 본인 신청 내역에만 허용한다.
- 신청 요청 시 개설 여부, 신청 자격, 정원, 중복 신청과 학교의 수강 제한을 서버에서 검증한다. 동시에 마지막 자리를 신청하더라도 정원을 초과하지 않아야 한다. `GET /enrollments/courses`의 `enrollmentCount`, `capacity`, `canEnroll`은 서버의 실제 신청 가능 여부를 반영한다.
- 교사가 수업을 확정할 때 서버는 `SCHOOL_ENROLLMENT_DATE`에 설정한 날짜를 수업에 저장한다. 화면의 빌드 설정 `VITE_ENROLLMENT_DATE`에도 같은 날짜를 넣고, 실제 신청일을 강좌 확정 전에 설정한다. 이미 확정된 강좌의 날짜를 변경하는 경우 저장된 일정도 함께 맞춘다.

## 개설 확정 수업 목록과 상세 정보

`GET /enrollments/courses`는 로그인한 학생에게 신청 전·신청 중·마감 후 모두 개설 확정 수업 목록을 반환한다. 신청할 수 없는 기간에도 수업을 조회할 수 있고, `canEnroll`은 `false`다. 목록에서는 수업별 신청 상태 대신 학교 공통 신청 기간을 사용해, 기간 중에는 모두 **수강신청중**, 기간 밖에는 **개설확정**으로 표시한다.

| 응답 필드 | 화면에서 사용하는 정보 |
| --- | --- |
| `id`, `title`, `category`, `status` | 수업 식별자, 제목, 분류, 수업 상태. `id`는 `/proposals/{id}` 상세 조회에 사용하는 제안 ID다. |
| `instructorName` | 실제로 수업을 맡기로 확정된 담당 선생님 이름 |
| `courseTime` | 확정된 운영 요일과 시간. 현재 화면은 표시용 문자열을 받는다. |
| `description` | 학생이 신청 전에 읽을 수업 설명 |
| `capacity`, `enrollmentCount`, `canEnroll` | 신청 화면의 정원, 신청 인원, 학생별 신청 가능 여부 |

담당 선생님이나 운영 시간이 미정이면 값을 비우고, 프런트엔드는 미정으로 표시한다. 실제 응답에는 체험용 예시 값을 사용하지 않는다. 제목에서 연결되는 `GET /proposals/{id}`도 로그인한 학생이 개설 확정 수업을 조회할 수 있어야 한다.

## 일정 투표 후보 요일

체험 모드의 예시 투표는 월요일·수요일만 사용한다. 실제 서비스에서 같은 정책을 적용할 대상 투표에는 서버가 월요일·수요일 슬롯만 제공하고, 기존 월요일·수요일 슬롯 ID를 유지한다.

| API | 연동 확인 사항 |
| --- | --- |
| `GET /proposals/{id}/vote` | 활성 후보와 해당 후보에 대한 기존 응답을 반환한다. |
| `PUT /proposals/{id}/vote` | 활성 후보에 대한 응답을 후보당 하나씩 받는다. 제거된 금요일 슬롯 ID를 포함한 새 제출은 거절한다. |
| `GET /proposals/{id}/vote/result` | 활성 후보만 반환하고, 제거된 후보 응답은 집계에서 제외한다. |

이미 진행 중인 투표에서 금요일을 제거할 경우, 기존 월요일·수요일 응답은 유지하고 투표 화면과 결과에 같은 후보를 적용한다.

## 수업 제안 목록 상태 필터

학생의 수업 제안 화면은 `SURVEYING`과 `VOTING`만 표시한다. 현재 프런트엔드는 `GET /proposals`의 단일 `status` 검색을 사용하고, 두 상태를 함께 보여줄 때는 응답을 화면에서 걸러낸다. 기존 API가 이 계약을 지원하면 화면 동작을 위해 별도 백엔드 변경은 필요하지 않다.

운영 데이터가 많아 표시할 항목을 채우는 데 여러 페이지 요청이 필요한 경우, 학생 목록에서만 쓸 다중 상태 필터를 추가할 수 있다. 필터는 정렬과 커서 페이지네이션 전에 적용하며, 단일 상태 검색과 다른 화면의 조회 범위는 기존 계약을 따른다.

## 연동 확인 항목

- 신청일 시작 1초 전과 마감 시각에 신청·취소를 직접 호출하면 거절되고, 기간 중에는 자격과 정원을 충족한 요청이 처리된다.
- 개설 확정 목록은 신청일 전후에도 조회되고, 담당 선생님·운영 시간·설명이 표시된다. 신청 기간의 배지가 전체 수업에서 같은 시각에 바뀐다.
- 기존 응답이 있는 일정 투표에서 월요일·수요일 응답이 유지되고, 금요일이 투표와 결과 모두에서 빠진다.
- 수업 제안 목록은 검색, 상태 선택, 더 보기에서도 수요조사 중과 일정 투표 중인 수업만 표시한다.

관련 경로와 응답 구조는 [API 연동 계약](API-CONTRACT.md)에서 확인할 수 있다.
