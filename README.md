# After — 우리가 만드는 방과후

방과후 수업을 찾아 관심을 표시하고, 후보 시간별 참여 가능 여부를 투표하는 React 프런트엔드입니다. 급식 평가 구현은 제거했습니다.

## Windows / macOS / Linux 실행

Node.js 20.19 이상 또는 22.12 이상이 필요합니다.

```bash
git clone https://github.com/After2026/After-fe.git
cd After-fe
cd frontend
npm ci
npm run dev
```

이미 클론했다면 저장소 루트에서 `git fetch origin`, `git switch main`, `git pull --ff-only` 후 `frontend`에서 실행하세요. 터미널에 표시되는 주소(기본 http://localhost:5173)로 접속합니다.

## 기능

- 수업 제안 목록: 검색, 상태·학년·분류 필터, 관심 인원·최신·마감 순 정렬, 커서 더 보기
- 제안 상세: 대상 학년, 개설 목표, 참여 의향 1~3과 의견 등록·변경·취소
- 일정 투표: 후보 시간별 가능 / 조정 가능 / 불가능, 모든 슬롯 응답 검증, 자격·마감 확인, 기간 내 재응답
- 결과: 시간별 응답 인원 표, 새로고침, 내 투표 수정
- 수업 제안 임시저장, 내 관심·제안 목록, 이용 안내, 잘못된 경로 처리
- 내 제안 상세에서 일정 투표가 시작되기 전까지 제안 수정 또는 삭제
- API 모드 로그인·승인대기 회원가입, 쿠키 기반 인증 및 토큰 만료 시 재발급

## 체험 모드와 API 모드

기본은 **체험 모드**입니다. 첫 접속 시 환영 화면이 표시됩니다. 상단에서 로그인·회원가입 화면으로 이동하거나, **지금 올라온 제안 보기**를 눌러 체험 모드로 예시 수업을 볼 수 있습니다. 로그인 화면에서도 **체험 시작 (회원가입 없이)**으로 들어갈 수 있습니다. 체험 세션은 탭 내 새로고침에서 유지되고, 수업 제안 목록에서 로그아웃하면 환영 화면으로 돌아갑니다. 실제 아이디·비밀번호 로그인과 가입 접수는 API 모드에서만 처리합니다. 예시 수업과 본인 응답만 이 브라우저의 localStorage에 저장합니다. 농구 수업에는 체험용 의향 2가 설정되어 바로 시간 투표를 해볼 수 있습니다. 예시 관심 인원은 고정된 샘플 수치이며, 결과는 이 브라우저에서 제출한 1명의 응답만 집계합니다. 비밀번호는 브라우저에 저장하지 않습니다. 다른 사용자와 공유하거나 실제 학교 투표를 진행하는 서버는 포함되어 있지 않습니다.

`frontend/.env.example`을 `frontend/.env.local`로 복사해 다음과 같이 설정하면 실제 API를 요청합니다.

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=https://YOUR_API_HOST/api/v1
```

변경 후 개발 서버를 재시작하세요. API 오류 시 체험 데이터로 대체하거나 저장 성공을 표시하지 않습니다. 인증은 `credentials: include`이며 Authorization 헤더를 사용하지 않습니다. 서버의 HTTPS, CORS origin 허용 및 쿠키 정책을 프런트엔드 배포 도메인에 맞춰 설정해야 합니다. 같은 도메인에서 `/api/v1`을 서버로 프록시하는 구성을 권장합니다.

## 연동 범위와 미확정 사항

첨부 API 초안에는 경로·권한·공통 규약만 있으며 상세 요청·응답 JSON은 없습니다. 구현이 가정한 필드는 [API 계약 문서](docs/API-CONTRACT.md)를 참고하세요. **실제 서버 연결 검증은 서버 주소와 확정 JSON을 받은 뒤 가능합니다.** Claude 링크는 차단되었지만 이후 첨부된 모바일·웹 디자인 이미지들을 직접 확인하여 화면을 맞췄습니다. 원본 폰트·아이콘·컴포넌트 파일은 제공되지 않아 시스템 폰트와 SVG 아이콘을 사용했습니다.

학생이 새 수업 제안을 올리면 바로 **수요조사중**으로 공개됩니다. 대상 학년 학생은 관심을 표시할 수 있습니다. 학교 선생님은 `/teacher`에서 제안을 맡고 월요일·수요일 후보와 마감 시각을 설정합니다. 수락 즉시 대상 학년 전체에 투표가 열립니다. 마감 후 담당 선생님이 투표 결과를 보고 후보 중 최종 시간을 선택하면 개설이 확정됩니다. 체험 모드에서는 로그인 화면이나 학생 화면 하단에서 **선생님 화면 체험**으로 전환할 수 있습니다. 실제 서비스에서는 `TEACHER` 계정으로 로그인합니다.

실제 제안 공개는 서버의 제안 접수 기간을 따릅니다. 기존 임시저장 제안은 작성자가 제출할 수 있습니다. 회원가입은 서버 연동 전 실제로 접수하지 않으며, 약관 원문은 운영 전 연결이 필요합니다.

## 검증 / 배포

```bash
cd frontend
npm test
npm run build
npm run preview
```

`dist`를 정적 배포하고 모든 프런트엔드 경로를 `index.html`로 연결하세요. `/api/v1`은 SPA fallback 대상에서 제외하세요. 테스트는 투표 자격·마감·전체 슬롯 검증, 재응답, 저장 유지, API 쿠키 인증·재발급 및 오류 처리를 확인합니다.


## 사용성 수정

- 로그인 상단의 중복 헤더와 로고 위 여백을 정리했습니다.
- 일정 투표는 독립 상단/하단 메뉴에서 제거했습니다. 수업제안 상세 또는 내 수업의 ‘일정 투표할 수업’에서 접근합니다. 이전 `/votes` 주소는 `/my`로 이동합니다.
- 투표 화면과 결과의 교시 표시는 숨겼습니다. 실제 슬롯 ID와 저장된 응답은 유지합니다.
- 체험 수강신청 인원과 진행 바는 현재 신청 내역을 합산해 계산하며, 취소하면 다시 줄어듭니다. 새로고침 후에도 유지합니다. API 모드에서는 신청·취소 성공 후 서버의 최신 인원을 다시 조회합니다.
- **개설 확정 수업**(`/courses`)은 로그인 후 언제든 볼 수 있습니다. **수강신청**(`/enrollments`)은 `frontend/.env.local`의 `VITE_ENROLLMENT_DATE=YYYY-MM-DD`에 지정한 날의 한국 시간 00:00부터 다음 날 00:00 전까지 열립니다. 실제 서비스는 교사가 강좌를 확정하기 전에 백엔드 `SCHOOL_ENROLLMENT_DATE`에도 같은 날짜를 설정합니다. 프런트엔드 설정을 바꾼 뒤 개발 서버를 재시작하거나 배포용 빌드를 다시 생성하세요.
- 신청일에는 개설된 관심 강좌가 신청 목록 상단에 고정됩니다. 개설 전 관심 강좌는 대기 카드에 표시됩니다.
- 알림함, 읽지 않은 수 배지, 개별/전체 읽음 처리를 추가했습니다. 체험에서는 저장된 관심 강좌가 개설 상태(CONFIRMED/ENROLLING/RUNNING)가 되면 중복 없이 알림을 생성합니다. 실제 API 모드에서는 서버의 알림 목록과 읽지 않은 수를 조회합니다. 화면 진입, 브라우저 포커스 및 30초 간격으로 갱신합니다.
- 앱 종료 후 Web Push는 포함하지 않습니다. 운영 서버의 개설 이벤트 처리와 Web Push 구독·발송이 필요합니다.
- 디자인 토큰 수집·저장은 요청에 따라 제외했습니다.
